# v1.2.0 骑行问题排查汇总

2026-10-08，六个独立会话已按用户的 1–6 序号完成只读排查。结论基于旧版代码、发布 APK/依赖、现有测试与历史日志；尚缺本次骑行的双端日志和设备信息，不能将候选原因写成现场已复现。

故障基线是 `v1.2.0`（code 3）：tag `d479ec1dec5c4c197785d69b88d0872a366946cb`，发布构建 `408bfbe6ee871b6c5d2aeba55aa641ae9f9ad0bb`，两者应用源码一致。比较基线为 main `0f5e7b778ee0b945725c9506055d6137a7faf546`（`1.3.0+aee3b3f` / code 4）。未使用当前日志开发分支的代码代替故障基线。

| 序号 | 初步定位 | 已确认与待验证 | 详细报告 |
|---|---|---|---|
| 1 多应用音频兼容 | 蓝牙 SCO 通信链路可能挂起媒体 A2DP；另有焦点丢失处理、通信模式释放缺口 | 通信链路与处理路径已确认；需故障时焦点栈、实际路由及第三方应用状态确认命中 | [多应用音频](01-multi-app-audio.md) |

建议先验证 VOX/手动静音的真实发送门控，再处理蓝牙路由与多应用音频；发现和重连按同一双端时序定位；降噪在实际头盔输入已确认后做受控比较。修复必须分别绑定真实事项和独立可审查改动；改变 T+10 连接契约或接纳新会话身份须按项目门禁审查，不直接放宽身份检查。

当前仅实施 KUM-62 日志升级，六项故障未在本轮修复。新版本安装后才会积累本机历史，无法补回 v1.2 当时未保存的诊断。后续优先补齐手机/Android/头盔型号、问题 5 错误原文和两端同步日志。
