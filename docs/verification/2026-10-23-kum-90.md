## 修复与边界

1. 无 selected/target attempt、连接地址、验证中物理组、隧道或 Socket，且正在发现时，普通断线通知不撤销启动查询和服务注册。活跃连接确认丢失、关闭及 stale 回调仍走原所有权链。
2. 固定 WebRTC 1.3.9 在 `read == capacity` 的捕获边界提供独立 `duplicate().clear()` 完整帧视图，保留原缓冲区游标；不放宽实际 PCM 格式、帧长、VOX、I/O revision 或 producer 校验。
3. 原 SDK 静音发生在处理回调之前。RNNoise 的历史输出可能把零帧写成非零；现在保存 SDK 本帧实际 mute 决定，并在回调后按绝对索引恢复全零。回调期间开启静音也生效，取消静音不能暴露本帧历史。字段、volatile 属性和读取点数量校验继续固定 SDK 契约，原生借用的 `keepAlive`/owner guard 未改。
