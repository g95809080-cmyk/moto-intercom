# 发布版本号约定

从本次正式版起，版本格式为 **主版本.次版本.修订号+已审查功能提交的短 SHA**，例如 `1.3.0+aee3b3f`。SHA 是 Git 提交标识，不是随机数。

- 兼容性修复增加修订号，例如 `1.3.1`；兼容的新功能增加次版本，例如 `1.4.0`；不兼容的协议、数据或对外行为变更增加主版本，例如 `2.0.0`。
- `+aee3b3f` 是 SemVer 构建元数据，正式版不使用会被解释成预发布的 `-aee3b3f`。构建元数据不参与版本优先级比较。
- `version.properties` 保存三段版本、严格递增的 Android `versionCode` 和用户审查通过并选择发布的完整功能提交 SHA。Gradle 从这里生成应用版本名；每次分发均递增 `versionCode`，已发布版本不覆盖。
- SHA 固定为用户批准的功能合并提交。本次为 `aee3b3f8be28b787665e4237addd0bbe4622c701`。随后仅进行版本配置、README 和发布记录整理，因此发布标签可以指向后续打包提交；标签记录实际构建源码，后缀记录获批功能基线。若之后修改功能代码，必须重新审查并更新基线，不能沿用旧后缀。

每次发布：确认获批基线在当前 main 历史中 → 检查基线后的差异仅为发布准备 → 更新版本配置与中文 README → 测试、Lint、构建 → 架构审核及 CI → 合并发布准备 → 从对应提交生成并沿用既有分发证书签名 → 核验 APK 版本、非调试属性、签名和 SHA256 → 创建 `v版本号` 标签及 GitHub 正式 Release，上传 APK 与校验文件。

发布说明记录功能范围、验证范围、完整获批基线及版本号；验证记录保存构建提交、检查结果、APK SHA256 与签名指纹。私钥不入库。

参考：[SemVer 2.0.0](https://semver.org/lang/zh-CN/)、[Android 版本管理](https://developer.android.com/studio/publish/versioning)。
