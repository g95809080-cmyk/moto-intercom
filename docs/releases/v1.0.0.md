## Included behavior

- Stable device identity, pairing, and single-writer product state.
- LAN and Wi-Fi Direct discovery and explicit rider selection.
- Target-locked signaling, deterministic connection attempts, fallback, and
  stale-callback rejection.
- Active disconnect while discovery remains online.
- Same-target recovery, bounded retries, wireless reset, and resource cleanup.
- Lock-screen/background keepalive.
- Phone speaker and Bluetooth headset audio routing.

## Physical acceptance

Two-device acceptance passed LAN and Wi-Fi Direct connection in both requester
directions, disconnect/reconnect, lock-screen and background audio, Bluetooth
headset route changes without duplicate sound, process restart, full Stop
without residual audio, a 30-minute call, and automatic recovery after a
Wi-Fi Direct outage.

The accepted residual risks are recorded in
`docs/verification/release-candidate-physical-plan.md`.

## Install

Download `MotoIntercom-v1.0.0.apk` from the GitHub release and install it on
Android 6.0 or later. For an existing development installation:

```powershell
adb install -r MotoIntercom-v1.0.0.apk
```

Android may require permission to install unknown apps when installing from a
browser or file manager.

## Rollback

Keep the previous debug-signed APK. Reinstall it with:

```powershell
adb install -r -d previous.apk
```

If Android rejects the downgrade, uninstalling first will work but deletes the
application's local pairing and identity data. No database schema migration is
introduced by v1.0.0.

## Not included

- Google Play or other app-store publication.
- Production signing-key guarantees.
- Formal RF/interference, battery/thermal, or third-physical-phone certification.
