# MotoIntercom v1.1.0 · Multi-audio intercom candidate

## Scope

This release candidate contains the current Compose multi-route UI, the
non-device audit follow-ups, and the multi-audio intercom coordination:

- automatic reconnect is a persisted setting with deterministic state-machine
  behavior; disabling it affects the next unexpected Connected loss and does
  not interrupt an active recovery attempt;
- Help is a real in-app dialog;
- Send Feedback uses an explicit `ACTION_CHOOSER` around an app-created
  `ACTION_SEND` text payload and does not attach session logs, recordings, URI
  data, or URI grants;
- the API 36 instrumentation job is part of GitHub Actions;
- Room/coroutine teardown in Robolectric tests is isolated between sandboxes.
- intercom communication audio requests `MAY_DUCK`, so compatible music and
  navigation players can lower their volume while intercom remains primary;
- telephony and communication-focus interruptions suspend intercom audio,
  keep call and intercom media isolated, and restore the full intercom route
  after the call returns to `IDLE`;
- permission messaging is deferred until the user explicitly starts
  intercom; rejecting the required permission prevents startup.

## Acceptance boundary

JVM tests, APK assembly, and API 36 emulator instrumentation are automated
gates. Two-device LAN/Wi-Fi Direct/WebRTC/Bluetooth behavior, Xiaomi 6/13 OEM
audio policy, third-party music/navigation duck compliance, RF conditions,
manual listening quality, battery/thermal behavior, TalkBack on physical
hardware, cellular/VoIP call injection, and release-device acceptance remain
deferred and must not be described as passed by this release note.

The exact test counts, APK digest, and CI run URL are recorded after the final
source gate in the accompanying verification evidence.
