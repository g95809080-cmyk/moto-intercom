## 结果记录约定

每项只记录以下状态：

- `PASS`：通过标准全部满足，证据已保存。
- `FAIL`：出现明确错误、崩溃、断音、未授权进房或结果不符合标准。
- `BLOCKED`：缺少第二台设备、头盔、蜂窝网络或其他必要条件。
- `NOT RUN`：本轮尚未执行。

证据统一使用“日期-时间 + 用例编号”，例如 `20261111-1410-B09`。失败时同时保存两端 App 的“设置 → 日志诊断 → 导出近 7 天日志”，并按需记录设备录屏和测试前后的网络状态。

## 验收档位

- **GME-FUNCTIONAL**：两台真机使用内置麦克风和扬声器，验证真实 GME 邀请、进房、双向语音、静音、退房和重连。该档不要求蓝牙头盔，也不用于证明头盔听感。
- **GME-BETA**：在 GME-FUNCTIONAL 基础上完成 10 分钟纯蜂窝双向语音、本地断链 fallback、锁屏、电话中断、杀进程恢复和标准蓝牙头盔验收。

没有蓝牙耳机时，可以进入 GME-FUNCTIONAL；只有 GME-BETA 才要求蓝牙头盔。测试内置音频时让两台手机相距至少 1–2 米，扬声音量适中，避免两台手机互相拾音产生回声。

## 阶段 0：测试准备

- [ ] 设备 B 安装同一个 APK，并核对 SHA256。
- [ ] 至少一台设备只使用蜂窝数据；建议设备 A 关闭 Wi-Fi 并关闭“自动连接已知 Wi-Fi”。
- [ ] 两台设备系统时间、时区正确，均已登录微信并连接互联网。
- [ ] 标准蓝牙头盔或耳机已分别在系统设置中完成配对，确认媒体音频和通话音频都已勾选。
- [ ] 设备 A 与设备 B 能接收通知；应用通知权限已开启。
- [ ] 设备 A 和 B 的麦克风、电话状态、附近设备/蓝牙权限均已按要求授权。
- [ ] 至少一台设备承担“升级安装”路径；另一台承担“全新安装”路径。
- [ ] 记录设备型号、Android 版本、网络类型、APK SHA256 和开始时间。
- [ ] 设备电量高于 50%，关闭自动省电限制，避免测试中被系统冻结。

全新安装只在设备数据可清空的测试机执行：

```powershell
adb -s <设备序列号> shell pm clear com.kuma.motointercom
```

## Beta 退出判定

第一轮 Beta 可以判定为通过，需要同时满足：

- [ ] B01–B43 全部 `PASS`，或剩余项有明确、不影响核心语音的书面豁免。
- [ ] 至少一次 10 分钟、一台纯蜂窝设备的真实 GME 双向语音通过。
- [ ] 邀请接受、拒绝、超时和忙线通过。
- [ ] 本地断链 fallback 通过，且首次连接失败不会误进云端。
- [ ] 锁屏、电话中断、杀进程后手动恢复通过。
- [ ] 标准蓝牙头盔的采音和播放通过。
- [ ] 两端日志、录屏、耗时和问题记录已归档。
- [ ] 没有崩溃、非法进房、重复音频、永久无声或持续啸叫。

正式版发布前还需要：

- [ ] B44–B50 全部通过，重点包括实际回切 ≤300ms、弱网、20 次进出和 4 小时上限。
- [ ] SNS 邮件订阅和腾讯 GME 用量告警实际触发成功。
- [ ] GME AppKey 完成生产前轮换。
- [ ] 测试结论写回 `docs/gme-validation-2026-11-10.json` 和交接文档。

## 日志采集命令

每轮开始前清空缓冲区：

```powershell
adb -s <设备序列号> logcat -c
```

失败后立刻导出：

```powershell
adb -s <设备序列号> logcat -d -v threadtime > beta-<用例编号>-<设备角色>.log
```

同时从 App 的“设置 → 日志诊断 → 导出近 7 天日志”导出应用日志。不要发送 AppKey、Secret、WebSocket token、设备私钥或 `authBuffer`。
