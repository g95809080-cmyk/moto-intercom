# 当前 UI 逻辑检查

后续状态：三项问题均已实施修复，见 [修复与验证记录](logic-fixes.md)。本文件保留修复前的诊断证据。

范围：当前工作区主页、发现、设置、日志的展示状态、点击回调、页面导航与状态回显。采用源码追踪、两个临时 Robolectric 回归探针和 API 36 模拟器实际操作。仅检查，未修改业务源码。

## P1：设置页提前报告音频通道就绪

位置：`MainScreen.kt:1127`，`renderSettings()` 调用 `homePresentation()` 未传入 `audioReady`，使用其默认值 `true`。首页和大屏详情则传入真实值。

复现：设置业务状态为 Connected，再设置 `audioReady=false`，从首页进入设置。临时测试实际输出：

```text
home=正在等待音频就绪
settings=当前状态：语音通道已连接
facts=计划通道：LAN；当前通道：LAN；WebRTC：已连接
```

影响：用户在尚不可通话时收到成功连接的反馈；大屏设置详情与设置正文也可能矛盾。应在设置的 presentation 构造中传入真实 `audioReady`，并覆盖未就绪、就绪和失去就绪三种回显。

## P2：音频快捷入口破坏设置页滚动恢复

后续导航更新：已移除残留的 `restoreSettingsAudio` 标记及跳过滚动恢复的分支，并新增“音频快捷入口 → 修改昵称/滚动 → 发现 → 设置”的草稿与滚动回归测试。音频快捷入口目前按普通设置入口保留页面位置，尚不自动定位到音频分组。下面保留原问题的诊断过程。

位置：`MainScreen.kt:697`、`:743`、`:794`。

首页音频按钮将 `restoreSettingsAudio` 设为 true。导航只用它跳过滚动恢复，既没有执行定位到音频分组，也没有将标记复位。临时测试确认进入设置后该标记仍为 true。

模拟器复现：点击音频图标 → 设置显示个人信息顶部 → 滚动到日志/关于区域 → 系统返回首页 → 点击右上角设置 → 又回到顶部。后续普通设置访问也持续跳过之前的滚动位置。

应在音频快捷入口完成一次分组定位并清除标记，普通入口继续恢复此前位置；VOX 快捷入口也应有明确的目标分组行为。

## P2：手机发现列表存在没有可见结果的点击区域

位置：`MainScreen.kt:912`，配合 `DiscoverScreen.kt` 的 `discover_select_*` 点击区域及 `MainScreen.kt:611` 的详情容器可见性。

车友头像和名称区域始终可点击，但点击回调仅记录 `expandedSelectedPresence` 并更新大屏详情容器。Compact/Medium 布局隐藏该容器，页面也没有选中态或其他反馈；离线设备缺少 sessionId 时甚至不会更新选择。无连接按钮的部分卡片还显示右箭头，进一步暗示可以进入详情。

影响：手机用户点车友名称/头像会认为无响应。单独的“连接”和“管理”按钮仍有各自有效回调。应为窄屏提供可见详情，或只在有可见详情面板时启用该区域，并同步调整箭头提示。
