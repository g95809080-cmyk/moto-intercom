# 摩声首次使用引导

基线：`0a67901`（2026-09-12），独立分支 `feat/first-run-onboarding`。现有 release-v1 工作区未提交改动不在本次范围内。

## 用户流程

首次进入 MainActivity 即显示本地说明图，标题说明“两台手机，就能边骑边聊”和“一对一离线对讲，无需互联网”。原图完整内置，长屏可浏览全图，小屏可滚动，底部固定“带我开始”和“跳过引导”。无需联网、注册或等待计时。

点击“带我开始”进入首页。教学依据真实 UI 状态选择目标，而非按固定延时推进：

| 当前条件 | 高亮目标与用户操作 | 推进条件 |
| --- | --- | --- |
| 缺少必要权限，尚未申请 | 首页实际启动按钮，解释权限并提供授权操作 | 原有权限回调报告真实结果 |
| 已申请但仍缺少权限 | 打开系统权限设置 | 返回后重新读取权限 |
| Wi-Fi 未打开 | 打开系统 Wi-Fi 设置 | 返回后重新读取 Wi-Fi 状态 |
| 可以启动且处于 Offline | 启动摩声 | Service 报告 Discovering |
| 已启动，位于首页 | 实际底部导航或侧栏的发现车友 | 用户明确点击并进入发现页 |
| 位于发现页且可扫描 | 重新扫描，解释连接与接受、连通后直接说话 | 点击扫描或“我知道了，自己试试”完成教学 |

“完成教学”不等于“首次连接成功”。没有第二台手机也能结束教学。只有现有产品状态为 Connected 且音频就绪，才将实际首次体验视为已达成，并结束仍在进行的教学。不会替用户选择车友或接受来电。来电确认、连接、恢复、停止等过程中隐藏教学，保留其进度。

每个阶段都可跳过，系统返回也视为明确跳过。设置 → 帮助与反馈 → 重新查看引导可重放；正在通话等忙碌状态下重放会等产品回到空闲/发现状态再出现。

## 持久化与布局

SharedPreferences 文件 `motocom_onboarding` 保存 `phase`（INTRO/TOUR/COMPLETE）、`hasShownGuide` 和是否申请过必要权限。只有完成或明确跳过才置 `hasShownGuide=true`；未完成则继续教学。无需服务端或新依赖。旧安装第一次更新到此功能也会展示一次，完成后不因普通升级重复；清除应用数据会重新展示。

教程是独立于产品状态机的 View 图层，加入现有 FrameLayout 并复用根视图安全区。Compose 按钮通过 boundsInRoot 报告真实局部坐标；绘制前结合宿主 View.getLocationInWindow 和原生 ScrollView 可视区重新计算挖孔位置。首个布局、滚动恢复和窗口变化时自动滚动使目标可见。横屏有足够侧面空间时，气泡放在目标侧边；其他情况在上下较大空间内显示可滚动气泡。

蒙层阻止误触背景；高亮区与气泡按钮调用同一现有业务回调，并在执行前重新校验最新事实。背景从无障碍遍历中隐藏，高亮代理提供可访问名称，说明图提供完整文字替代。完成/隐藏时恢复背景可访问性。

## 基线兼容修复

`0a67901` 的 MainScreen 已有四处调用 homePresentation 时传入 audioReady，但该提交的函数签名缺少参数，无法编译。本次仅补入该函数的音频等待展示逻辑，并测试未就绪与就绪的文案区别。未移入 release-v1 工作区的 BLE、音频引擎或协议实验改动。

## 验收范围

验证首次图文展示、跳过/完成后重启不重复、未完成和权限拒绝后重建续接、真实按钮点击、过期 START 回调不能变成 STOP、来电确认让位、横屏和滚动恢复、音频未就绪不提前宣告成功。设备截图与自动测试结果记录于对应 verification 文档；模拟器教学验证不替代双真机对讲与听音验收。
