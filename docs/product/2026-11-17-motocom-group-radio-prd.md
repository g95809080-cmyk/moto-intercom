## 1. 结论

摩声群组电台是一个本地优先、网络延伸的骑行对讲产品。群主建组，队员输入房间码或邀请码加入；本地模式面向 2–4 人小队，网络模式面向最多 50 人的单公共频道大群。网络媒体由火山引擎 RTC（veRTC）承载，控制面继续由 `tools/group-cloud` 管理成员、邀请、审批和群主治理。

首发范围冻结为：

```text
本地 4 人
  + 群主控制
  + 骑行官 / 头车 / 尾车
  + 公共 / 领队 / 私聊
  + 蓝牙耳机 / 后台 / 锁屏

网络 50 人
  + 单公共频道
  + 邀请码 / 审批
  + 群主转让 / 解散 / 成员移除
  + veRTC 音频选路与 Token 续签
```

网络 50 人仅通过独立 `groupPreview` 变体交付，不改变主线和本地 4 人模型。

## 2. 背景与问题

当前 Android 主线是一对一对讲，用户在骑行小队场景中会遇到四个缺口：

1. 3–4 人无法在同一房间内稳定互听。
2. 群主无法移除成员、结束全队或指定骑行官。
3. 全组公共语音之外，领队和骨干缺少独立沟通频道。
4. 两名成员需要私聊时，只能退出群或另开一对一，破坏骑行连续性。

ASMAX 的可借鉴点不是它的耳机固件 Mesh，而是产品结构：一个群会话承载成员、角色、房间和链路；公共、领队、私聊是群内逻辑房间；网络模式是单云端房间。摩声用 Wi‑Fi Direct 替代手机侧 Mesh，因此需要把“直通模式”和“云端集群模式”拆清楚，不能把 Wi‑Fi Direct 当成真 Mesh。

## 3. 产品目标与非目标

### 3.1 产品目标

- 2–4 人骑行小队在无路由器、无互联网环境下，30 秒内建组并开始说话。
- 群主能管理成员和结束全队；骑行官/头车/尾车有明确角色。
- 公共、领队、私聊三种频道切换清晰，任何时刻只听到一个频道。
- 蓝牙耳机、锁屏、后台、来电中断下仍可正常使用。
- 网络模式可让最多 50 名成员跨网络加入同一云端公共房间。
- 网络大群不污染本地四人模型、主线 1:1 对讲和主线安装包。

### 3.2 非目标

- 不复刻 ASMAX 耳机固件 Mesh、dpId、UUID、Mesh 帧或 OTA。
- 不做 10/50 人本地 Wi‑Fi Direct 全互联。
- 不做 HUD、导航、音乐分享、胎压、设备控制、广告、社交动态。
- 网络模式采用 veRTC，不回到自建全互联 WebRTC、TURN 或 `/signals` 中继。
- 不承诺本地/云端同时混跑或灵犀级无缝切换。
- 不默认录音、不上传语音、不做语音回放。

## 5. 产品模型与规则

### 5.1 概念

```text
车队 Fleet
  └─ 群组 Group
       ├─ 公共频道 Public
       ├─ 领队频道 Rider
       └─ 私聊频道 Private
```

- 一个群只有一个 `GroupSession`。
- 公共、领队、私聊是群内频道，不是三个新群。
- 每个成员同一时刻只有一个 `currentChannel`。
- 频道切换只改变可听成员集合和媒体路由，不重新创建群。

### 5.2 角色

| 角色 | 权限 | 默认频道 |
|---|---|---|
| 群主 `OWNER` | 建群、解散、移除成员、解除限制、任命/撤销骑行官、结束全队 | 公共 |
| 骑行官 `RIDING_OFFICER` | 进入领队频道，查看领队成员 | 公共，可切领队 |
| 头车 `HEAD` | 编队标识，默认进入领队频道 | 领队 |
| 尾车 `TAIL` | 编队标识，默认进入领队频道 | 领队 |
| 普通成员 `MEMBER` | 公共频道、私聊、查看成员 | 公共 |

头车/尾车是否属于领队频道由群配置决定，默认包含。产品不把角色做成组织树，只作为频道权限和展示标识。

### 5.3 频道规则

| 频道 | 可进入 | 行为 |
|---|---|---|
| 公共 | 全体已准入成员 | 默认频道，全组互通 |
| 领队 | 群主 + 骑行官 + 头车 + 尾车 | 仅频道内成员互通；其他人继续留在原频道 |
| 私聊 | 发起方 + 接受方 | 1:1；必须对方接受；关闭后回公共 |

规则：

- 一个成员同一时刻只在一个频道。
- 私聊一个成员同一时刻最多一个。
- 私聊不改变群成员关系。
- 群主移除成员或成员退群时，相关私聊自动关闭。
- 网络模式只做单公共频道，不暴露领队/私聊；业务群主 `ownerId` 与本地宿主 `hostDeviceId` 分离，网络房间的 `hostDeviceId = null`。

### 5.4 容量与模式

| 模式 | 容量 | 传输 | 频道 |
|---|---:|---|---|
| 本地 `LOCAL` | 4 人 | Wi‑Fi Direct | 公共、领队、私聊 |
| 网络 `NETWORK` | 50 人 | veRTC + 控制面 | 公共 + 成员管理 |
| 双模 `HYBRID` | 4 人 | 本地优先，云端兜底 | 公共、领队、私聊 |

本地容量硬上限 4 人，不因系统理论连接数放宽。网络容量默认 50 人；大群 AppID 必须在火山控制台开启「音频选路」，否则默认房间的发布/订阅上限为 30 路。

### 5.5 权威与生命周期

- 本地模式：群主同时是本地房主；群主离开需要确认结束全队。
- 网络模式：群主是业务角色，`tools/group-cloud` 是成员与房间状态权威，veRTC 只承载媒体；群主离开必须转让或解散。
- 双模模式：云端是业务权威，本地房主只负责 GO 和本地链路，不自行增加云端不存在的成员。
- 房主/GO 失联：本地模式保留 60 秒恢复窗口，不自动选举；超时结束。
- 双模模式：本地失联后切云端，整组切换，不并行。
- 被移除成员本次会话不能重新加入；解除限制后才可回。

## 7. 核心流程

### 7.1 创建与加入

1. 群主进入群组页，点击创建。
2. 完成麦克风、附近设备、蓝牙权限。
3. 本地模式创建 Wi‑Fi Direct GO 并生成六位码；网络模式由控制面生成 8 位邀请码。
4. 本地队员输入六位码完成带外认证；网络队员输入邀请码提交加入申请。
5. 网络房间在需要审批时由群主准入；准入后服务端签发 RTC Token。
6. 双方看到成员名单和语音状态；网络模式仅在在线成员达到 2 人后加入 veRTC。

### 7.2 公共通话

1. 默认进入公共频道。
2. VOX 检测到说话自动开麦；用户可自静音。
3. 每个成员看到谁在说话、谁暂不可听。
4. 本机可单独屏蔽某个成员，不影响其他人。

### 7.3 切领队频道

1. 群主或有权限成员点击频道切换。
2. 选择领队频道，确认当前频道和可听成员。
3. 系统关闭旧频道媒体，建立领队频道媒体。
4. 切换完成后 UI 显示“领队频道”，未授权成员不可进入。

### 7.4 私聊

1. 成员在名单中选择对象，发起私聊。
2. 对方收到呼叫，接受或拒绝。
3. 接受后双方离开原频道，建立 1:1。
4. 任一方关闭，双方回公共频道。

### 7.5 掉线与恢复

1. 成员网络中断，其他成员看到“恢复中”。
2. 席位保留 60 秒。
3. 成员重新加入，回到原频道。
4. 超时未回，席位释放；群主可重新邀请。

### 7.6 群主结束

1. 群主点击结束全队。
2. 二次确认，说明所有成员会退出。
3. 广播结束，关闭媒体，释放 GO/云端房间。
4. 所有成员回到群组准备页。

- 每个成员的在线和语音状态。
- 离开/结束入口。

## 9. 非功能需求

### 9.1 性能目标

| 指标 | 目标 |
|---|---|
| 本地创建到首句可听 | P50 ≤ 15 秒，P95 ≤ 30 秒 |
| 六对成员语音就绪 | 受控测试 ≥ 95% |
| 频道切换 | ≤ 3 秒，成功后无旧频道声音 |
| 私聊建立 | ≤ 5 秒 |
| 60 秒恢复 | 受控测试 ≥ 90% |
| 云端语音延迟 | P95 ≤ 300 ms（参考 ADR，待实测） |
| 崩溃率 | 无崩溃会话 ≥ 99.5% |

### 9.2 音频

- 语音优先，16 kHz 单声道；具体编码参数由技术设计固定。
- 蓝牙耳机、听筒、外放可切换；切换不重建群。
- 来电时暂停对讲；电话结束后按现有音频协调器恢复。
- 同一成员不能同时从本地和云端出声。

### 9.3 安全与隐私

- 本地六位码与网络 8 位邀请码只用于带外认证，不出现在广播、日志、通知正文。
- 本地使用 PAKE/加密控制通道；云端使用短期会话令牌与 veRTC Token。
- 服务端不保存客户端 GME/高德等第三方密钥。
- 默认不录音、不上传语音、不保存语音消息。
- 被移除成员的旧凭证立即失效。

### 9.4 兼容性

- Android 6.0 及以上；Wi‑Fi Direct、BLE、蓝牙能力按设备检查。
- 不支持 Wi‑Fi Direct 的设备不显示本地群入口，或明确提示不可用。
- OEM 差异、P2P client isolation、蓝牙 SCO 共存必须真机矩阵验证。

### 9.5 可访问性

- 触控目标不小于 48dp。
- 支持大字体和屏幕阅读器。
- 频道、静音、离开、结束都有明确语义，不只靠颜色。

## 10. 指标

### 10.1 核心指标

- 创建成功率、加入成功率。
- 创建到首句可听时间。
- 本地 4 人 6 对语音就绪率；网络 50 人 RTC 进房率与活跃发言人可见率。
- 频道切换成功率、私聊建立成功率。
- 60 秒恢复成功率。
- 每周群组骑行场次、7 日内二次骑行率。

### 10.2 质量护栏

- 双路音频/重复语音事件为 0。
- 未授权加入、错误码加入为 0。
- 房间码、邀请码、RTC Token 与 AppKey 进入日志/通知为 0。
- 房主失联后“幽灵成员”为 0。
- 本地 4 人以上被静默接纳为 0。

## 11. 版本规划

| 版本 | 范围 | 退出条件 |
|---|---|---|
| R1 工程 MVP | 本地 4 人 + 公共频道 + 群主移除/结束 | 4 台真机 6 对互听；无路由器；2 小时稳定 |
| R2 产品首发 | R1 + 角色 + 领队/私聊 + 频道切换 | 切房/私聊/移除/恢复全部通过；可对外演示 |
| R3 网络版（历史） | 自建 WebRTC/TURN 的 4 人单房间 | 已由 R4 取代，不再作为发布路线 |
| R4 大群版 | veRTC 50 人单公共房间 + 成员管理 | 50 人房间稳定；音频选路/静音/重连/Token/额度护栏通过 |
| R5 双模版 | 本地优先，整组切云端 | 断线切云、恢复切回、无双路音频 |

R2 是第一个真正体现 ASMAX 群组价值的版本。R4 单独立项，不与 R1/R2 混做。

## 12. 依赖与风险

| 项 | 影响 | 处理 |
|---|---|---|
| local-group 分支落后主分支 | 不能直接合并 | 按阶段移植，保持双人默认不变 |
| OEM P2P client isolation | 4 人每对 WebRTC 可能不通 | 先实测；必要时 GO 侧桥接或降级 |
| 无 4 台真机 | 无法完成硬件验收 | 代码/模拟器通过不等于可发布 |
| veRTC 配额与音视频路数上限 | 50 人大群发布/订阅失败 | 大群 AppID 开启音频选路；服务端与客户端都校验容量；监控 `-1080` / `-1070` |
| 单人空转计费 | 10,000 分钟免费额度被快速耗尽 | 待审批/单人等待不进房，回落 1 人立即退房；50 人满员每分钟按 50 分钟计 |
| AppKey / OpenAPI AK/SK 泄漏 | 可伪造 RTC Token 或管理 RTC 房间 | 仅保存在服务端 `.local` 或环境变量，严格 gitignore，禁止下发客户端 |
| 蓝牙 SCO 与 Wi‑Fi Direct 共存 | 音频路由冲突 | 复用现有 AudioRouteController，真机矩阵 |
| GME 分支只有 1:1 实验 | 不能当群组底座 | 不作为主路线 |

## 13. 待决事项

以下事项不影响 R1，但会影响 R2/R4：

1. 群主离开是“必须转让”还是“允许直接解散”？建议网络模式必须二选一，本地模式直接结束全队。
2. 领队频道是否默认包含头车/尾车？建议包含，并允许群主配置。
3. 网络模式是否只做公共频道？已确认是，避免 50 人房间权限过早复杂化。
4. 是否在 R2 提供 PTT？建议先 VOX，PTT 作为 R2.5 可选。
5. 50 人大群是否与首发同一产品线？已确认使用独立 `groupPreview` 变体和独立运营入口。
