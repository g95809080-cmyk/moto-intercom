# KUM-62 设计

## 来源与所有权

由 Application 初始化唯一进程内诊断 runtime；现有 Android Log 调用改用兼容包装，保留 Logcat 输出，同时异步保存。Service 的 publishLog/status/error/audio-source 在分发给 UI 之前记录，UI 自己产生的权限/操作记录也保存。捕获现有音频路由、WebRTC/VOX、Wi-Fi Direct、信令及群组诊断；不读取系统或其他应用 Logcat，不记录 PCM/完整 SDP/认证材料。

诊断组件不参与连接、目标、通道、音频或产品状态决策；SessionOrchestrator 与既有音频所有权保持不变。

## 留存与性能

纯 Kotlin 文件 store 接收时间、级别、tag、消息，逐条 UTF-8 落盘。时间使用 epoch 毫秒与 UTC 可读格式。按 1 MiB 分段；滚动 168 小时保留，初始化、读/导出和在线定时维护时清理过期记录。总预算 256 MiB；RiderAudioEngine 每秒 VOX DEBUG 快照只在持久化侧每 5 秒采样，原 Logcat 频率不变，状态变化与错误全部保留。预算验证以真实带 epoch/UTC/tag 的记录计算 168 小时常态数据量。极端日志风暴超出预算时停止新记录，不删除尚未过期的历史；预留空间记录缺口计数，容量恢复后自动继续。清理只操作专用诊断目录的文件。

一个后台 worker 串行执行写入、清理、读取和导出，队列限制 512 个命令。主线程及音频回调只做非阻塞入队；超载丢弃计数写入下一条诊断。磁盘失败返回明确错误/Logcat 信息，不能抛入通话路径；之后允许恢复写入。不持有 Activity。

消息有长度限制，换行和制表符转义以避免伪造记录。认证字段脱敏；异常记录类型、消息与有限栈帧。进程退出后已完成的写入保留，尚未执行的有限队列不保证在强杀时落盘。

## 页面与导出

日志页后台加载最近 300 条，可复制当前显示内容，独立按钮通过 ACTION_SEND 系统选择器导出近 7 天日志文本。FileProvider 仅开放专用导出目录，授予所选接收方临时读权限；不自动发送，也不更改原反馈模板。每次生成独立不可变文件/URI，24 小时后清理，后续导出不能删除尚在寿命内的旧文件。导出缓存预算 512 MiB；达到上限时明确失败并保留先前文件。关闭/重建 Activity 不影响保留日志。

仅日志页可见且 Activity 活跃时定时刷新，读盘和导出始终在后台，返回主线程时校验页面/生命周期；离开或销毁后取消刷新。导出按钮显示准备状态，失败可重试；队列满时读/导出也必须收到失败回调。每条记录保存来源应用版本/API/运行实例，导出头另包含设备型号、导出时间/时区与保留策略。Service 已采集的记录由 UI 仅展示，不重复持久化；回放状态不重新记为事件。认证字段脱敏覆盖 ice-ufrag/候选 ufrag 扩展。

## 验证

确定性文件测试：进程/store 重建、精确 7 天边界、跨日连续使用清理、分段与容量、真实 168 小时采样预算、损坏尾行、并发写入、读取/导出顺序、磁盘失败后恢复、脱敏与队列饱和。Android 集成覆盖 Application/后台 Service 记录、Activity 重建、两次导出后第一份 URI 仍可读、导出 URI/权限和空日志/准备/失败 UI。跑必要回归、完整 JVM、Lint、debug 构建；固定 SHA 只读架构审查。未安装到用户手机前不声称真实骑行验证通过。
